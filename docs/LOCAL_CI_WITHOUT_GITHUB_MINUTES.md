## Бесплатный маршрут А: собрать на Windows напрямую

На Windows ПК (не на Android-телефоне) установи: Python 3.12, **JDK 17**, **Gradle 8.9** (в этом репозитории нет Gradle wrapper), Android Studio SDK Platform 35 + Build Tools 35.0.0. Должны работать команды `python`, `javac`, `gradle`. Установи переменную `ANDROID_HOME` на каталог Android SDK. Не скачивай неизвестные «готовые APK» и не устанавливай сомнительные программы; использовать официальные установщики.

Клонируй приватный репозиторий и перейди в папку проекта, затем:

```powershell
git clone https://github.com/skynet909084-boop/BLOODSKY-Android.git
cd BLOODSKY-Android
git switch feat/fbd-75-pin-semantics
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_bloodsky_windows.ps1 -UiProfile None
```

**Пока скрипт находится только в изолированной ветке этой заявки, сначала переключись на `ci/offline-windows-selfhosted-20261018`** или дождись проверки/слияния этой заявки в FBD-ветку.

После успешной сборки APK будет в `app\build\outputs\apk\debug\app-debug.apk`. Локальный запуск не использует лимит hosted-minutes. Эмулятор необязателен для JUnit и APK. Для полного UI установи Android Emulator и создай/запусти одноразовый Android 11 (API 30) x86_64 AVD, затем повтори с `-UiProfile Full`. Скрипт откажется запускать очищающие UI-проверки на настоящем телефоне. Режим Quick допускается только после принятия и слияния проверенного кода PR #108.

## Бесплатный маршрут Б: собственный Windows runner прямо в GitHub

Можно сохранить привычные кнопки/логи GitHub Actions без оплаты hosted-minutes. Работа выполняется **на твоём ПК**, а не на виртуальной машине GitHub. По актуальной официальной документации self-hosted runners не расходуют GitHub-hosted minutes. Компьютер должен быть включён, подключён к интернету и поддерживать установленную среду; это не бесплатный компьютер в облаке.

1. Открой <https://github.com/skynet909084-boop/BLOODSKY-Android/settings/actions/runners>.
2. Нажми **New self-hosted runner → Windows → x64**.
3. Выполни на своём Windows ПК **именно те команды**, которые GitHub выдаст для скачивания, `config.cmd` и `run.cmd`. При настройке добавь специальную метку `bloodsky-local` (в дополнение к стандартным `self-hosted, Windows, X64`). Токен регистрации одноразовый/короткоживущий: **не присылай его в чат и не записывай в репозиторий**.
4. Настрой Python, JDK, Gradle и SDK, как в варианте А, именно для того пользователя Windows, под которым работает runner.
5. Когда ПК отображается в GitHub как **Online / Idle**, открытый PR с изменённым `.github/workflows/bloodsky-selfhosted-windows.yml` может поставить задание на твой runner. Изолированная ветка и новый workflow сейчас не меняют `main`. Прямой `workflow_dispatch` для нового workflow появится только после размещения его файла на default branch; до этого предусмотрен триггер PR, запускающий только **твой собственный PR**, а не чужие fork.
6. После запуска: смотреть Actions → BLOODSKY free self-hosted Windows build. Сборка/тесты выполняются локально; APK загружается в артефакты GitHub с хранением 2 дня для минимизации платного хранения.

### Безопасность self-hosted runner

- Оставь репозиторий **приватным**. Не делай весь проект публичным для обхода лимита: у него есть сторонние Craft-ресурсы и собственные материалы, которым не место в публичной копии без отдельного аудита прав.
- Runner исполняет код из репозитория на личном ПК, поэтому не разрешай непроверенные PR и секреты, используй отдельного пользователя Windows с минимумом прав. Этот workflow ограничивает авто-триггер PR владельцем репозитория и выдаёт токену только `contents: read`.
- Работа runner идёт через исходящее подключение GitHub; не нужно открывать порты роутера или выкладывать RDP/SSH наружу.
- Никакие GitHub-hosted минуты таким способом не создаются и месячный лимит не «обходится» обманом; вычисления официально переносятся на свою машину. На облачное хранилище артефактов ограничения по-прежнему действуют.

## Следующие шаги

1. Проверить Billing на аккаунте владельца, чтобы подтвердить исчерпание 2000 минут.
2. Поднять локальный Windows build через `scripts/build_bloodsky_windows.ps1`; при наличии безопасного эмулятора выполнить Full.
3. Подключить свой runner, подтвердить **реальным** зелёным Actions-запуском. Пока runner не зарегистрирован, workflow законно будет ждать и нельзя писать «CI PASS».
4. После успешной проверки слить этот инфраструктурный PR в рабочую FBD ветку #76 (не `main`), вести журнал фактических SHA/run/тестов.
5. Завершить оставшиеся исходные FBD CTU/RS/BLINK и лишь затем планировать стабильный релиз.

Основная контрольная точка: `docs/FBD_EXECUTION_HANDOFF_20261017.md` в #76 и issue #75. Старые принятые этапы заново не реализовывать.

Официальная документация: https://docs.github.com/en/actions/concepts/billing-and-usage, https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/add-runners .
