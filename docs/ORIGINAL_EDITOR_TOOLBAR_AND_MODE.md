# Original upper toolbar and operator mode

Source: pinned Craft 1.0.7 reference SHA-256 `316da0335dc4ea0c8f2d8c14550118ba33bd0e95d7c926f67ed848429c554cdd`, `activity_work_portrait.xml/toolbar`, `mbCanvas.onClickWorkToolbar`, `B0/C0`, `s0.onClick`, `onClickSetNameScreen` and `onBackPressed`.

The source 40dp row replaces BLOODSKY's three large toolbar rows. Deterministic extraction retains child order, dimensions, margins, colors, IDs and original bitmap bytes. XML reflection handlers become explicit accessible bindings. The source clock TextView adapts to a native TextClock (HH:mm) so its lifecycle remains Android-managed. Battery and lock retain source hidden states. The unimplemented project-document control is explicitly disabled rather than opening unrelated content.

Run/stop uses original start/stop icons. Entering or leaving runtime first requires successful synchronous project publication, clears pending FBD-wire selection and rebuilds the view without mutating widget geometry. Runtime hides the component palette, selection actions, grid, selected-widget handles and FBD editor visuals. Existing FBD evaluation is still run before hidden block rendering is skipped; this is not a claim of complete original FBD execution semantics. Editor taps now open component properties instead of activating buttons/setpoints/navigation.

OperatorGesture separates runtime taps from edit gestures. Short same-target taps invoke existing button/setpoint/navigation behavior; drags, long presses, cancellation and a second pointer cannot open editor properties, move or resize elements, or activate controls. Back stops runtime first; another Back autosaves and returns home. Reopening after process death starts in editor mode with previously saved operational state, avoiding an automatic run. Polling keeps the existing foreground/session safeguards and is retained in editor preview as before.

The source hide/reveal icons and bottom-left component icon are connected. The toolbar is above the canvas in BLOODSKY's vertical host; hide/reveal therefore changes the available viewport rather than using the original full-screen overlay. Original right settings menu, password return-to-edit, runtime screen-lock semantics, project PDF viewer, charging display, background service and full original theme remain outside this slice. Existing project/screen commands remain reachable through a native project popup; this popup is an explicit platform adaptation, not the source `menu_` dialog. No schema changes, transport implementation or release signing.

Validation: complete transferred toolbar hierarchy and bitmap checks, explicit bindings/unsupported control checks, executable pure gesture tests and existing regression suites. Extended emulator scenario verifies hide/reveal, original calculator/palette/image/clipboard flows, editor-button properties without activation, runtime tool removal, drag/long-press rejection, operational toggle with no unrelated field changes, stop/Back, process restart and button-state persistence. Exact-head APK/unit/emulator gates and screenshot inspection are required before acceptance. Local Gradle/SDK unavailable; local Python suite passes.
