# Original indicator ON/OFF image editor

The indicator properties form now exposes “Сменить изображение”. It opens the original two-state menu and original five-image library from Craft 1.0.7 `dialog_menu_image_lamp.xml` and `dialog_choose_image_lamp.xml`; source handlers are `r.h0.o/k`, and persisted state fields come from `CustomComponents.q.getJsonOther`.

Pinned reference SHA-256: `316da0335dc4ea0c8f2d8c14550118ba33bd0e95d7c926f67ed848429c554cdd`. All hierarchy/attributes, ON/OFF positions, dimensions, title text/color and bitmap resources are retained. IDs are prefixed and original resource literals resolved using the same tested utility as the component palette. Dialogs use a scoped native dark theme. Full original AppCompat theme/pixel parity on equal devices remains unverified.

Selecting green/yellow/red/blue/off updates only the selected state's `isImageUserOn/pathOrNameOn` or `isImageUserOff/pathOrNameOff`, preserving the other state, unknown metadata and flat/object/string `other` representation. Changes use an isolated JSON copy and synchronous existing catalog publication. A reported save failure restores the prior widget metadata and screen snapshot; stale widget references cannot be edited. Existing callers retain the asynchronous project-save wrapper.

The original custom-picture action opens an Android-compatible path/file form and existing Storage Access Framework picker. Persistable read grants use the existing picker callback. Apply validates that the image can actually be decoded; invalid/unavailable images keep the dialog open. This path/file form is a platform adaptation, not a claim of identical original file-browser UI. Missing grants after process death are handled by the existing callback (no unverified path is applied).

Project images use existing bounded media reads (10 MiB), header-only bounds inspection before pixel allocation, power-of-two sampling to at most 2048 pixels on each edge, and a 32 MiB/128-entry cache budget. Built-in images retain original resources. Large external images exceeding the portable bundle limit are rejected rather than loaded without bounds.

Coverage: complete original XML hierarchy/attribute equality, original bitmap provenance through existing indicator tests, pure metadata edits for all three representations, unknown-field preservation, no mutation on invalid input, snapshot/codec round trips and extreme image sampling bounds. The emulator exercises both original dialogs, changes ON to red and OFF to blue, selects a real custom yellow PNG from the Android Downloads document provider, verifies the content URI/flags after process death and reopens the original preview using the persisted grant alongside existing fractional geometry, calculator, palette and catalog deletion checks. Other document providers, real devices and equal-density original APK comparison still require additional checks; no hardware behavior or release parity is claimed.

The first emulator attempt reached Downloads with the real PNG visible. DocumentsUI grid rows report filenames in accessibility descriptions rather than text; the helper now supports both the observed grid format and list text, with a dedicated regression test and an unchanged mandatory post-restart URI/state check.

The API30 emulator exposed an additional shell-input issue: repeated taps at settled list filename bounds did not activate DocumentsUI. Android 11's `cmds/input/Input.java` creates the legacy MotionEvent without explicit PointerProperties, while RecyclerView selection routes gestures by tool type. The shell-only `BloodskyFingerTap` test driver explicitly supplies `TOOL_TYPE_FINGER` and injects the DOWN/UP events as the emulator shell user. It is built only by the UI-test workflow and is never packaged into the app. Real DocumentsUI selection, URI persistence, decoding and post-restart assertions remain mandatory; exact-head CI establishes whether this resolves the observed failure.

Source references: https://github.com/aosp-mirror/platform_frameworks_base/blob/android-11.0.0_r1/cmds/input/src/com/android/commands/input/Input.java and AndroidX `GestureRouter`/`SelectionTracker` tool routing. The earlier grid/list timing theory alone did not resolve the emulator failure; stable filename bounds are retained for deterministic targeting.
