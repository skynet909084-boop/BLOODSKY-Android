Preview `CH_F` uses numeric input `F`, BOOL output `Q` and drawing kind 8. Default Java state is zero, unless restored by constructor (no saved BLOODSKY live state).

Versioned BLOODSKY extended-palette operators: `FBD CRAFT CHANGE I` NUMBER `I` -> BOOL `Q`, and `FBD CRAFT CHANGE F` NUMBER `F` -> BOOL `Q`. Both use the source-accurate pure functions in `FbdCraftChangeTransitions`, transient prior-value state (not saved into project JSON) and a gray source split-header drawing. All input connections must be explicitly named and present; missing/nonfinite signals fail closed to false without modifying the saved last value. Integer inputs must be finite **exact signed INT32**; Float inputs cast to Java Float32 and reject overflow/NaN/Infinity rather than propagating invalid values. Float32 quantization means fluctuations below float precision do not cause spurious pulses.

**Compatibility limits:** original absent input exposes null from `getOut()`; BLOODSKY's BOOL API displays false for missing input. This is an intentional fail-closed approximation, not full original Java nullable output semantics. The original Float source uses Java `!=`; NaN would count as change each scan, but unsafe nonfinite control signals are explicitly rejected here. Existing BLOODSKY CTU, R_TRIG, SEL, timer and HMI projects are unchanged. Original preview `FB_CHANGE_I/F` stays disabled until real Android palette/UI acceptance after JUnit+APK tests.

JUnit `FbdCraftChangeTransitionsTest` covers pulses, held values, 0 startup, signed INT32 limits, Float32 precision, full MainActivity graph scan, reconnection behavior, pin types/compatibility and transient state save/load. `FbdSourceNativeCanvasSkinTest` checks source gray default and 1/2 wire terminal fraction.
