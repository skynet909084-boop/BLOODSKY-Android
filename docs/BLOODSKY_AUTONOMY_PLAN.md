# BLOODSKY — автономный план разработки

Цель: сделать так, чтобы GitHub сам проверял каждое изменение, регулярно собирал APK, сохранял артефакты и явно показывал блокирующие ошибки. Это автоматизирует проверку и выпуск сборок; оно не заменяет разработчика и само по себе не может безопасно реализовывать новые функции без отдельного coding-agent runner и выданных ему прав.

## Постоянная автоматизация
- На каждый push/PR в коде приложения, инструментах или CI: проверить архивный инспектор, выполнить Android unit-тесты и собрать debug APK.
- По расписанию: повторно прогонять тесты и сборку даже без новых коммитов.
- Сохранять APK как GitHub Actions artifact с ограниченным сроком хранения.
- Не публиковать релиз и не подписывать production APK автоматически секретным ключом.
- При сбое: сохранять логи в GitHub Actions; не считать этап завершённым, пока зелёный run не подтверждён.

## Очерёдность продуктовых этапов

### P0 — надёжная основа
- [x] CI для Python-проверок архивов, Android unit-тестов и debug APK.
- [x] Отдельные тесты на повреждённый JSON, небезопасные пути и повторяющиеся ZIP-имена.
- [ ] Проверить зелёный GitHub Actions run после последних изменений.
- [ ] Добавить тесты сохранения/загрузки проекта и round-trip JSON без потери неизвестных полей.

### P1 — совместимость редактора
- [ ] Сверить экраны, панели, меню, шрифты, цвета, размеры и состояния с оригинальным Kaskada Craft 1.0.7.
- [ ] Составить инвентаризацию всех компонентов, их свойств и контекстных меню по декомпилированным ресурсам.
- [ ] Закрыть критерии редактора: создание, выбор, перемещение, изменение размера, копирование, удаление, несколько экранов и сохранение.
- [ ] Не заявлять pixel-perfect до проверки реальными скриншотами рядом с оригиналом.

### P2 — runtime и протоколы
- [ ] Тесты привязок тегов и периодического обновления значений.
- [ ] Modbus TCP: чтение holding/input registers, обработка тайм-аутов, ошибок и отключений.
- [ ] Modbus RTU: определить Android-совместимый транспорт и аппаратные ограничения до реализации.
- [ ] Проверить логику FBD: циклы, порядок выполнения, значения и обработку ошибок.

### P3 — качество и выпуск
- [ ] Проверить импорт реальных проектов Kaskada на тестовых копиях, не перезаписывая оригиналы.
- [ ] Добавить регрессионные тесты на каждый найденный дефект.
- [ ] Проверить установку APK и базовые сценарии на реальном Android-устройстве.
- [ ] Подготовить отдельную подписываемую release-сборку только после проверки ключей и релизного процесса.

## Критерии завершения
- CI зелёный на актуальном commit SHA.
- APK существует как скачиваемый артефакт и устанавливается.
- Все обязательные тесты проходят; известные ограничения записаны.
- Для визуального паритета есть проверенные сравнения с оригиналом.
- Ни один отчёт не говорит «готово» только потому, что workflow был запущен.

## Границы автономности
GitHub Actions может выполнять команды, тесты, сборки и проверки по расписанию. Он не должен самостоятельно менять архитектуру, принимать сомнительные решения о совместимости, публиковать релиз или обходить защиты. Для автономного написания кода нужен отдельный агент с ограниченными разрешениями, тестами, review-процессом и возможностью отката.

## Issue-driven coding agent

The implementation and security contract for progressing from automatic CI to bounded autonomous coding is documented in [BLOODSKY_SAFE_AUTONOMOUS_AGENT.md](BLOODSKY_SAFE_AUTONOMOUS_AGENT.md). Track provider/runtime configuration and the first pilot in [Issue #2](https://github.com/skynet909084-boop/BLOODSKY-Android/issues/2). Code-writing automation must remain disabled until its execution environment and narrowly scoped credentials are configured and reviewed.
